## 2. Acceptance invariant

For a check with incoming size `S`, safety reserve `R`, and reservations already committed and not released `P`:

> **accept iff** `min(max(0, Q_limit - Q_used), F_free) >= P + S + R`, and on accept, a reservation of `S` bytes is durably committed before output.

Where `Q_*` is account quota and `F_free` is the filesystem's unprivileged free bytes (`f_bavail * f_frsize`).

| Quantity | Status | Source |
| --- | --- | --- |
| `Q_used`, `Q_limit` (quota mode) | **Observed** at check time | `quota -w -p -u <uid>`, row matched to the verified device |
| `Q_limit` (directory mode) | **Configured/attested** by the operator (`quota_bytes`) | config |
| `Q_used` (directory mode) | **Observed** as an *upper estimate* of visible tree bytes | `scan_usage` |
| `F_free` | **Observed**; a ceiling only. Never substitutes for account quota. | `os.statvfs` |
| `P` | **Reserved** (ledger); counts full logical sizes, so it can double-count | SQLite `reservations` |
| `S` | **Observed** from Autobrr `{{ .Size }}`; unknown or zero rejects | argv |
| `R` | **Configured** | config |
| Scope completeness, no external writers, no manual `release` of live downloads, no stricter group/project/provider quota | **Operator-attested only.** No code can verify these. | `scope_confirmed`, `startup_pending_confirmed` |
| Host visibility vs. container visibility | Host runs prove host visibility only. Managed-container visibility is **not** established by any run here. | `diagnose` note, `tests/docker` |

No finite test suite proves absolute storage safety. The owner must review this evidence before changing repository visibility.

## 5. Findings

### F1 — Ambiguous duplicate JSON keys silently accepted (fixed)

- **Reproduction** (unpatched `3a6ac71`): config contains `"reserve_bytes":1000000,"reserve_bytes":1`, available 1000, size 999. Observed: exit 0, `accept`, 999 bytes reserved. The operator's file says reserve 1,000,000, so this should have been rejected. Python's `json` silently keeps the last duplicate.
- **Why unsafe:** the file an operator reads does not match the effective configuration, so the reserve can silently be lower than intended.
- **Regression:** `tests/test_quotaguard.py::ConfigTests::test_duplicate_json_keys_rejected`. Failed on `3a6ac71` ("Block not raised").
- **Patch:** `object_pairs_hook` raises `Block` on any duplicate key.
- **Status:** fixed. Suite passes; E7 passes.

### F2 — Unexpected exceptions escape as a traceback with exit 1 (fixed)

- **Reproduction** (unpatched): `secrets.token_hex` raises `NotImplementedError`. Observed: exit 1, a Python traceback on stderr, no JSON. Exit 1 is the "insufficient space" status, and the traceback can contain private paths. This contradicts the documented contract (`docs/SAFETY.md` and README: JSON output, exit 2 for unknown conditions).
- **Regression:** `LedgerTests::test_unexpected_exception_is_reported_as_reject_without_traceback`. Errored on `3a6ac71`.
- **Patch:** a final `except Exception` in `main()` returns the generic reject with exit 2. `BaseException` subclasses such as `KeyboardInterrupt` still propagate. The ledger context manager still rolls back uncommitted work, so the fallback approves nothing.
- **Status:** fixed. E5 passes.

### F3 — Zero-byte or partial ledger after an interrupted `init` (documented, not patched)

A crash between `O_EXCL` file creation and the `init` transaction leaves an empty `reservations.sqlite3`. Subsequent `init` fails with "exists", and `check` rejects. This fails **closed** (E6 zero-byte passes), but recovery needs manual deletion of the empty file. The operator should verify the state directory before deleting anything. Recommended operator note; no code change, because automatic deletion would weaken the ledger guarantee.

### F4 — Directory traversal race coverage (NOT RUN here)

`scan_usage` uses `os.scandir(path)` after an `lstat` check. A directory swapped for a symlink in that window is followed by `scandir`. The final validation pass should still reject, because the directory's `(ino, ctime)` changes when renamed away. I did **not** verify this on Linux. It needs a POSIX rename race test on Linux, which is NOT RUN here.

### F5 — Operational limits (documented, unchanged)

- The ledger `BEGIN IMMEDIATE` holds the write lock during directory scans of up to 10 s, and `busy timeout` is 1 s. Concurrent checks reject with "database is locked". That is fail-closed but reduces throughput. Not measured under real scan load.
- `release` requires a successful `measure()`. If quota or the scan fails, a stale reservation cannot be released. This is fail-closed and needs operator awareness.
- The config fingerprint includes tuning fields (`scan_timeout_seconds`, `max_entries`). Changing them requires ledger reconciliation. This is intentional but surprising.
- Hard timeouts cannot interrupt a hung NFS `lstat` in uninterruptible sleep. SIGALRM only fires between syscalls.

## 8. Unresolved assumptions

- Quota-mode `used` is the account's allocated blocks. Stricter group, project, or provider quotas are invisible to this tool.
- Other writers, manual downloads, and `release` misuse can defeat the ledger. Only the owner can prevent these.
- Autobrr macro rendering and argument splitting were not exercised against a running Autobrr. The documented template uses only the numeric `{{ .Size }}` macro.
- Managed HostingByDesign container compatibility is unverified.
